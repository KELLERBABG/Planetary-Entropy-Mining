The idea

01 · Provenance

The problem

Emission and offset certificates are issued by registries, so their audit trail is paperwork held by the issuer. A buyer has to trust the registry instead of checking the measurement.

Physical measurement offers a way out. A window of environmental noise is unique, cannot be precomputed and cannot be produced on demand by a party that was not there.

How it works

A node captures that window, reduces it to a histogram and estimates its min-entropy with the NIST SP 800-90B estimators. A zero-knowledge circuit proves the histogram clears a min-entropy threshold and that the node holds the matching GF(256) hardening polynomial and nullifier.

The certificate then travels as erasure-coded shards across an intermittent mesh, matches in a blind dark pool, and settles once per nullifier so the same measurement cannot be claimed twice.

Deterministic per node and per window, so one measurement can be claimed once.

Onion layers over X25519 and AES-GCM, so a relay learns neither origin nor destination.

Blind crossing in the dark pool, then atomic pay-once-per-nullifier on chain.

What the circuit proves

03 · The gate
// stated in the circuit header I know a 256-bin histogram of 2^16 quantised samples whose most common symbol occurs at most 512 times — hence the per-symbol min-entropy is at least -log2(512 / 65536) = 7 bits and a 64-byte GF(256) hardening-polynomial commitment, and a node secret, such that the public nullifier equals Poseidon(secret, node_secret, p_commit).

The gate is enforced twice over: every bin count must stay under max_count, and max_count × 2T must stay under the sample count. Lowering the bound below the true maximum breaks the first check, and raising it breaks the second, so a prover has no room to move.

The compiled circuit ships its own constraint system and witness generator: entropy_audit_poly.r1cs and the WebAssembly witness calculator beside it.

Limits

04 · What is simulated
  • The physical sources are seeded simulators. Real piezo and SDR capture sits outside this repository, and the estimators are validated against modelled truth rather than against hardware.
  • The settlement ledger runs in memory. The Solidity contract is the specification; the chain is not exercised.
  • The Solidity verifier checks the public layout. Pairing maths is not verified, and swapping in the snarkjs-exported verifier is a documented one-file change.
  • Foundry was not runnable on the build machine, so the Python twin of the settlement suite is the one that is green.

Run it

05 · On a laptop

Python 3.11 or newer. The zero-knowledge stage needs Node for circom and snarkjs.

git clone https://github.com/KELLERBABG/Planetary-Entropy-Mining
cd Planetary-Entropy-Mining
py -m pip install -e ".[dev]"

py -m pytest -q                 # fast suite
py -m pytest -m ""              # adds the slow 1M-bit NIST tier
py -m cli.validate              # entropy report into docs/
py -m cli.demo --quick          # end-to-end chain, Python only

node circuits/scripts/entropy_poly_prove.mjs --assert

The reference implementation runs every stage as a deterministic simulation, so the protocol can be specified, tested and audited without hardware. The cryptographic core — GF(256) field arithmetic, X25519 and AES-GCM onion layers, Shamir secret sharing — is real.
